A Commit Law for Noisy Evaluations

the agent writes the change, the noise sets the bar

Abstract. An agent loop keeps a change when the score goes up. But an evaluation that samples its cases is noisy: the same code scores differently on every run, so "up" is often luck. keeploop keeps a change only if it beats the best score by more than the evaluation's own measured noise (best + 2σ), with the rule that rejects it fixed before the run, one confirm re-run, and a fresh-context Auditor reading the real diff. On a deliberately noisy benchmark, over seeds fixed in advance, a naive keep-if-better loop kept changes with no true gain per run; keeploop kept . 1Introduction

An agent saying "done" is not a measurement, and one score is not one either. A sampled evaluation answers with noise: in the example below the same configuration scores a little differently on every call, with a spread of σ = measured from its baseline runs.

2The Loop

Each cycle tests one written hypothesis with the smallest change, and a number decides (Algorithm 1). A gain inside the noise band is not evidence, so it is not committed.
